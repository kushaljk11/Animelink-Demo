Non-functional requirements describe **how well the system should perform**, rather than what features it provides.

- **Security:** User accounts, passwords, vaccination records, and sensitive information should be protected using secure authentication, authorization, validation, and encrypted communication.
- **Performance:** The system should load important pages, maps, and records within a reasonable response time under normal usage.
- **Usability:** The interface should be simple, clear, responsive, and easy to use for pet owners, vets, rescue organizations, and municipal users.
- **Reliability:** Important data such as vaccination records, incident reports, and CNVR information should be stored consistently and should not be easily lost or corrupted.
- **Availability:** The application should be accessible through modern web browsers and available whenever users need to access important records or reporting features.
- **Scalability:** The system architecture should allow more users, pets, clinics, wards, and records to be added as the platform grows.
- **Maintainability:** The codebase should use modular and reusable components so features can be updated or extended easily.
- **Responsiveness:** The application should work properly across desktop, tablet, and mobile screen sizes.
- **Accessibility:** The interface should use readable text, clear navigation, accessible form controls, and both Nepali and English language support.
- **Data Privacy:** Only authorized users should be able to access private pet owner, clinic, incident, or administrative information.
- **Data Integrity:** Important records, especially veterinarian-verified vaccination records, should include validation and controlled editing permissions.
- **Compatibility:** The system should work on commonly used modern browsers such as Chrome, Edge, Safari, and Firefox.
- **Geospatial Accuracy:** Location-based features should use reliable coordinate data and clearly indicate when user-provided GPS data may be approximate.
- **Backup & Recovery:** Important application data should be backed up so it can be restored in case of failure.
- **Extensibility:** The system should be designed so additional modules and features can be added later after further research, brainstorming, and supervisor feedback.
